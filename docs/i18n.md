# Languages

Yapfast reads in English, German and French, and the settings page can offer
any of the 32 languages Discord has once someone writes its translations.

## How a text is translated

Every text is its English wording; the wording is also its key. There is no
message id to invent and no English file to keep in step.

- `yapfast_core::i18n::tr("Mute server")` answers with the text in the chosen
  language, as a `&'static str`, so it goes wherever the literal did:
  `text(tr("Mute server"))`.
- A text with values is `fill(tr("Kick {}"), &[&name])`; `fill` puts the
  values in for `{}` in order and for `{0}`, `{1}` by place, so a language can
  put them in the order its sentence needs. A count that changes its word is
  `trn("{n} friend", "{n} friends", count)`.
- A sentence is one text. Give each variant its own (`if group { tr("... this
  group ...") } else { tr("... this server ...") }`) rather than slotting a
  translated word into one, since a language may inflect the word by gender or
  case. Where a word must be slotted (`Create {}` with "channel"), keep it a
  bare noun.
- A text with no translation reads in English, so a missing string is never
  blank.
- A word that means two things in English takes a context, for example the
  months and weekdays of the clock (`tr_ctx("month", "May")`).
- Dates and times come from `clock.rs`, which asks the catalog for the weekday,
  month, period (AM/PM) and date patterns, so a language rewrites all of them
  in its `.po` file.
- A constant or static can't call `tr`. Mark its text with `later("Never")`
  (the text itself, which the extractor finds) and call `tr(text)` where it is
  shown.

The files are `translations/<code>/LC_MESSAGES/yapfast-ui.po`, where `<code>`
is Discord's code for the language (`de`, `fr`, `pt-BR`). A translated
language's file is embedded in the program (`include_str!` in
`crates/yapfast-core/src/i18n.rs`), read by that file's own small parser when
the language is first needed, and kept.

A text that is compared must not be translated on one side only: a person's
status is kept as the English word the core gives, and shown with `tr`.

The kit (`yapfast-iced-kit`) knows nothing of the core, so it never calls
`tr`. A component takes the text it shows from the window, which translates
it, except the few the kit draws itself ("Reset", "Save Changes", "LIVE"):
those go through `words::say` and `words::say_with` (one `{}`), which the
window points at `tr` once with `words::translate_with` when it starts. The
extractor reads those calls in the kit too.

## Which language shows

The layout saves `interface_language`, Discord's code for the choice. Unset, it
follows the system language (`Language::system`), and English when Yapfast has
no translation for that. Settings → Appearance lists English (US and UK) and
every language that has translations (`Language::offered`); choosing one
switches at once, and the window draws its texts again.

Tests share a process, so one that needs a language of its own calls
`i18n::pin_language`, which keeps it to the thread; the window's tests start
in English whatever the machine's language is.

## Keeping the files in step

`scripts/i18n` needs only Python 3.

    scripts/i18n extract     write translations/yapfast-ui.pot from the code
    scripts/i18n update [L]  merge the texts into each language's .po file
    scripts/i18n check       placeholders, plural forms, coverage, style
    scripts/i18n todo L      list the texts L has not translated

`update` finds the texts by reading the Rust sources (`tr(`, `later(`, `tr_in(`,
`trn(`, `tr_ctx(` and the clock's phrases). It adds new texts empty, keeps the
translated ones and says which texts the code no longer has. `check` fails
when a translation changes the placeholders of its text, has the wrong number
of plural forms, contains an em dash, or does not keep the text's leading and
trailing spaces, and when a file has a text the code no longer says.

Translate with the product's wording in mind: Discord's own terms for Discord
features, and the sentence in the register the language uses for a program
(German "du", French "vous").

## Adding a language

1. Add the language to `LANGUAGES` in `scripts/i18n` with its plural rule
   (`one-other` for German or English, `zero-one-other` for French; add a key
   to `PLURALS` for another rule).
2. `scripts/i18n update CODE` writes `translations/CODE/LC_MESSAGES/yapfast-ui.po`
   with every text empty.
3. Translate the texts. `scripts/i18n todo CODE` lists what is left.
4. In `crates/yapfast-core/src/i18n.rs`, add `translated` to the language's
   `locale!` line. That embeds its file and makes the settings page offer it.
5. `scripts/i18n check` must pass.
6. Look at the screens: German and French run 20 to 40 percent longer than
   English, and a label that fits in English can overflow. The languages that
   need more than a plain Latin font (Chinese, Japanese, Korean, Thai) also
   need their glyphs; check the bundled fonts first.

## What stays English

Names (Yapfast, Discord, Matrix, Nitro, Klipy), key names, protocol and
file-name literals, log and crash messages, and the emoji names Discord sends.

Some texts are not yet translated because they are not produced by the window:

- Discord's `<t:...>` timestamps in messages, which `yapfast-discord` formats
  with English patterns.
- Texts the core builds before the window sees them, such as the audit log
  entries and some notices.
- The names of Discord's own things that Discord sends already localized or in
  English (emoji names, sticker packs, activity names).
- Command-line help and `--version` output.
