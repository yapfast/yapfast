# Integration and finishing: waves 2 to 5

The I tasks put the core behind the screens: each fills `anomi-app`'s
`project/<area>` (the core's `AppState` as the area's view-model, ported
from `src/ui/refresh.rs`) and `intent/<area>` (the area's intents as
`Action`s, ported from `src/ui/callbacks.rs`), and runs the effects the area
needs. They are Opus tasks in the one integration worktree, one at a time
(its first build costs minutes and several GiB; see the README). Each runs
once its screen tasks pass review, and is accepted on the real backend under
`scripts/ui-session --anomi` against the same shots. The Q tasks finish the
move. See [the index](../tasks.md).

`~/.cache/anomi-iced/state/upstream-reference.md` is a reference built from upstream Yapfast's own iced window, one section per task: their files for the area, what carries over to ours, and the bugs and traps their fix commits record. Before writing, the integrator reads its task's section and the reference's "Traps for every I task".

**How a task plugs into the spine (I01's).** *Projection:* write `project/<area>`'s `show(state, [layout,] &mut vm.<area>, &mut shown.<area>)`, which rebuilds only when its key changed, and add its line to `project::refresh` under the `Reach`es that can change it (`project/reach.rs`: `STATE` always, then `TYPING`, `VOICE`, `PICTURES`, `EMOJI`, `PICKER`, `VIDEO`; a backend event shows only the areas it reaches; an action those `Reach::after` names, as Slint's `Adapter::action` (`src/ui.rs:3228`) narrowed them: a keystroke in a composer or an edited message `COMPOSER`, in a bot's form or the poll being made `FORM`, in the profile editor `EDITOR`, in a server's or a channel's settings or the two-factor prompt `SETTINGS`, in the quick switcher or the new DM's field `PLACES` (narrower than Slint's), the pictures asked for and `VisibleMessages` nothing) and its key to `Shown`. *Intents:* `intent::handle` already routes every `anomi_vm::Intent` to `intent/<area>`: a view-model change ends in `app.refresh()` (or `app.show(reach)`), a core change goes through `app.dispatch(action)`, which shows what `Reach::after(&action)` names; one another area acts on is routed in `intent/mod.rs` ahead of its area's arm, and a layer the area opens closes through its arm in `intent/shell.rs`'s `close`. *Effects:* `effects::run` already hands each `Effect` to its module's `run(app, effect) -> Task`. Settings the core doesn't keep are `app.layout` (`layout/saved.rs`, the Slint `Layout` field for field): read through `Deref`, changed with `app.layout.edit(|saved| ...)`, written a second later; a wait of the app's own is `app::later(delay, message)`; `App::for_tests(folder)` gives a test an app without a window.
